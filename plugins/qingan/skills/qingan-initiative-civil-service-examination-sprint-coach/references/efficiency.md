# 考公效率评估系统

效率评估回答的不是“今天够不够努力”，而是“投入有没有转化为更稳定的正确、速度和回测闭环”。默认运行 `python3 "SKILL_ROOT/scripts/qingan.py" --data-dir "DIR" evaluate`，再把结果翻译成一个调整动作。

## 五个观察面

| 观察面 | 看什么 | 常见误判 |
|---|---|---|
| 执行 | 计划任务完成率、任务粒度是否可持续 | 时长很长就等于执行好 |
| 准确 | 同类题正确率、第一错误断点、迁移表现 | 一套卷波动就代表能力退步 |
| 时间 | 同类训练的单位时间正确数、超时与止损 | 跨模块比较“每小时做对几题” |
| 回测 | 到期错题是否处理、提示依赖是否下降 | 看过解析就算闭环 |
| 证据 | 样本量、题源、计时条件、前后周期是否可比 | 数据少也给精确趋势和综合分 |

## 评估顺序

1. 先查数据够不够：至少有训练时长和题量；判断趋势还需要可比的前一周期。
2. 再分别报告执行、准确、时间、回测和覆盖，不合成一个神秘总分。
3. 标出置信度：`low / medium / high`，并说明缺少什么。
4. 只选择一个当前瓶颈：证据、执行、回测闭环、方法、覆盖或时间策略。
5. 给下一周期唯一调整动作和复查日期。

代码中的完成率和变化幅度阈值只是路由启发式，用来决定先检查哪一层，不是及格线。最终解释必须结合题型、难度、样本和生活约束。

## 记录可比较的训练

用 `record-session` 写入实际时间、作答数、正确数。想看跨周变化时，附上 `comparison_key`，例如“资料分析｜真题同比增长｜闭卷限时｜相近难度”。更换题型结构、难度、独立作答方式或计时规则就换口径名。两个周期各至少 20 道同模块同口径题，才计算对应组的变化。多个可比组各自报告，并说明每组样本量。

旧会话和缺少口径的会话继续计入本周观察，等两组可比数据再判断涨跌。错题卡附上训练会话的 `session_id`，既保留错因证据，也避免和会话统计重复加题。报告的错因计数是错题卡次数。

周主攻候选取各模块题量最多且至少 15 题的单一口径组，按错率排序。并列时考虑同机制在不同题上的复发和同口径每小时答对数的下降。缺口径的记录只作为暂定依据。跨模块每小时答对题数受题型、阅读量和分值影响，汇报时保留为各自的训练观察。

## 比较边界

- 只在题型、难度、题源和计时方式相近时比较速度。
- 正确率上升但题目更简单，不能直接宣称进步。
- 完成率低先检查计划是否脱离课程、工作与精力，不先归因于自律。
- 学习时长上升但正确率、迁移和回测都不变，优先改练法，不继续加时。
- 样本不足时输出“先建立基线”，不硬评效率。

## 周评输出

```text
证据置信度：
本周观察：执行 / 正确 / 时间 / 回测 / 覆盖
与上周可比的变化：
当前唯一瓶颈：
下周只改这一件事：
下次复查条件：
```

语气针对过程，不给人打分。可以说“这份计划的颗粒度太大”，不要说“你执行力差”。
