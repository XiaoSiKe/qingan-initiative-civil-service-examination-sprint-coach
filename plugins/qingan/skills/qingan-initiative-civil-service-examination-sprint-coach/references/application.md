# 报考与选岗协议

报考咨询分成“能不能报、报什么、流程怎么走”。涉及年份、地区和职位条件时，先读取 `source-policy.md` 与 `official-sources.md`，打开当年公告和职位表原文再回答。

## 最小输入

只收集会改变判断的信息：目标考试与年份、地区、学历学位、专业及代码、应届身份、政治面貌、基层经历、资格证书、户籍/生源限制，以及地点、岗位类型和最低服务年限偏好。不要索取身份证号、准考证号、家庭住址等不必要信息。

## 能不能报

逐列核对职位表，不用经验猜：学历、学位、专业目录、身份、政治面貌、基层经历、证书、户籍/生源、性别或体能等合法职位要求、备注栏。输出“符合 / 不符合 / 需招录机关确认”，并给出对应列和原文位置。

专业名称接近不等于符合。公告、专业目录和职位备注冲突或含糊时，建议按公告联系方式咨询招录机关，并保留咨询记录。

## 报什么

先过硬条件，再比较个人偏好，不替用户做决定。推荐矩阵：

| 维度 | 核对内容 |
|---|---|
| 资格确定性 | 是否存在专业、身份或备注争议 |
| 工作匹配 | 地点、职责、基层/夜班/出差、服务年限 |
| 考试匹配 | 试卷类别、专业科目、体测或其他环节 |
| 机会成本 | 与学业、工作、其他考试的时间冲突 |
| 竞争信息 | 只用可核验历史数据，绝不预测分数线或“包稳” |

## 输出

区分三类内容：稳定制度方法、当年官方事实、用户偏好判断。附具体公告或职位表链接、发布日期、核验日期和仍需确认的问题。报名提交前提醒用户自行复核原表；Skill 不代替资格审查。
